# AI 개발 원칙

> 이 프로젝트에서 AI 코딩 도구를 쓰는 7가지 원칙. "완전 자동화"가 아니라 **검증 가능한 개발 루프**가 목표.

1. **바로 구현을 맡기지 않는다.** `Research → Plan → Approve → Implement → Test → Review → Handoff`를 강제한다.

2. **계획 승인이 먼저다.** 구현 전 코드베이스 리서치와 계획서를 만들고, **사람이 승인한 계획만** 구현한다. 리서치가 틀리면 계획·구현이 다 틀린다.

3. **AI 결과물은 항상 검증한다.** 테스트·타입체크·lint/format·코드리뷰 체크리스트를 통과해야 한다. 검증할 수 없는 것은 커밋하지 않는다.

4. **실수는 규칙이 된다.** AI가 반복하는 실수는 `CLAUDE.md`의 "알려진 함정"에 누적해 같은 실수를 줄인다. 팀이 함께 기여할수록 규칙이 쌓인다.

5. **도구는 필요한 것만.** hook·MCP·skill을 많이 붙이는 게 목적이 아니다. 실제 반복 업무와 검증 루프에 필요한 것만 둔다(컨텍스트·유지비 절약).

6. **위험한 자동화 금지.** 자동 `git push`, 자동 대량 파일 수정, 매 작업마다 뜨는 과한 알림 hook은 만들지 않는다. push/PR은 사람 승인 후.

7. **통제 가능성이 목표.** 실무진이 봤을 때 "이 사람은 AI를 통제 가능한 개발 프로세스로 쓴다"고 느끼게 한다. 속도는 AI, 품질·통제는 검증 루프.
