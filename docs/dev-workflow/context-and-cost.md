# 컨텍스트 · 비용 · MCP 관리

> 컨텍스트는 가장 중요한 리소스다. "신선하고 필요한 것만" 유지한다.

## 컨텍스트 관리
- **관계없는 작업 사이 초기화** — 새 작업 전 컨텍스트 클리어. 리서치로 쌓인 컨텍스트는 계획 확정 후 정리.
- **논리적 분기점에서 압축** — auto compact에 의존하기보다, 성능 저하 전(대략 절반쯤)에 수동으로 요약·압축.
- **두 번 실패하면** 컨텍스트를 비우고 더 구체적인 프롬프트로 재시작.
- **CLAUDE.md는 짧게**(150~200줄). 상세는 `docs/`·서브에이전트로 분리(필요할 때만 로드).

## 도구·MCP는 필요한 것만
- MCP·도구를 많이 붙일수록 컨텍스트를 도구 정의가 잠식한다. **필요한 것만 활성화.**
- 프로젝트별로 안 쓰는 MCP는 비활성화. 단순 작업은 CLI(`gh`·`bq` 등)가 MCP보다 가볍다.
- MCP 도입은 **실제 반복이 확인된 후**(예: 이슈 트래커·DB 반복 조회). 처음부터 여러 개 붙이지 않는다.

## 모델 선택 (참고)
| 상황 | 모델 |
|---|---|
| 일반 코딩(대부분) | 중간 모델 |
| 복잡한 설계·아키텍처·보안·여러 파일 | 상위 모델 |
| 단순 반복·명확한 지시 | 경량 모델 |

→ "계획은 상위 모델, 실행은 중간 모델"처럼 단계별로 나눠 쓰면 비용·품질 균형.
