# 검증 피드백 루프

> "AI가 만든 코드를 어떻게 믿을 수 있게 만들었는가"에 답하는 문서. **검증할 방법을 주면 결과 품질이 크게 올라간다.**

## 원칙
- 구현 후 **바로 커밋하지 않는다.** 검증 통과가 커밋 조건.
- AI에게 **검증 명령을 함께 준다**(테스트·빌드·타입체크). AI가 스스로 결과를 확인하고 고치게.
- 검증할 수 없는 변경은 배포하지 않는다.

## 도메인별 검증 (onramp-api)
| 도메인 | 검증 방법 |
|---|---|
| **애플리케이션 로직** | `make test-unit` — 유닛 테스트. 외부 의존(Qdrant·OpenAI·DB)은 목/픽스처로 격리 |
| **API 엔드포인트** | `make test-integration` + `make dev` 띄우고 `curl localhost:8000/...` 로 응답·상태코드 확인. `/docs`(OpenAPI) 스키마 확인 |
| **DB / 마이그레이션** | `make migrate` → `make migrate-down` 왕복 확인. 인덱스·쿼리 실행계획 확인. 테스트는 aiosqlite 인메모리 |
| **RAG 검색** (리트리버·청킹·리랭커) | **`make eval-gate`** — 골든셋(`data/eval/queries.jsonl`·`qrels.jsonl`) 지표 게이트. 변경 전후 비교. **지표가 안 오르면 그 변경은 폐기 후보** |
| **생성 품질** (프롬프트·답변) | `make eval-gen` (RAGAS LLM-judge). **비결정적 → CI 게이트로 쓰지 않는다.** nightly·수동 참고 지표 |
| **LangGraph 그래프** | 노드 단위 유닛 테스트 + Langfuse trace로 실제 실행 경로 확인 |
| **비동기 코드** | `pytest-asyncio` (`asyncio_mode=auto`). 이벤트 루프 누수·미await 코루틴 경고 확인 |

## 공통 검증 스텝 (커밋 전)
1. **테스트 실행** — `make test` 통과. (없으면 실패 테스트를 먼저 작성 후 구현 = TDD)
2. **타입체크** — `make typecheck` (mypy `app/`) 오류 0.
3. **lint/format** — `make lint` 통과 (수정은 `make format`).
4. **(RAG 변경 시) 지표** — `make eval-gate` 로 골든셋 하락 없음 확인.
5. **변경 요약** — 무엇을·왜 바꿨는지 한 문단.
6. **위험 파일 확인** — `.env`·시크릿 미접근·미커밋.
7. **`git diff` 리뷰** — 의도한 변경만 있는가. 커밋 메시지에 `(#N)` 있고 `Co-Authored-By` 없는가.

## 코드 리뷰 체크리스트 (`/review-checklist`)
- [ ] 버그·논리 오류·엣지케이스 누락 없음
- [ ] 보안(인증·입력검증·비밀 노출) 문제 없음
- [ ] 성능(불필요 반복·N+1·메모리) 문제 없음
- [ ] 기존 패턴과 일관, 불필요한 복잡도 없음
- [ ] 테스트가 실제 동작을 검증(무의미한 통과 아님)

## 재검증 루프
수정 → 검증 → (실패 시) 다시 수정 → 검증. **오류가 0이 될 때까지** 반복. 사람은 이 루프의 승인자.
