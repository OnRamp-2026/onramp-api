# 리서치 + 계획 (/research-plan)

> **구현하지 않는다.** 리서치 → 계획서까지. 승인은 사람이 한다(→ `docs/dev-workflow/workflow.md`).

## 입력
작업/기능 설명, 관련 있어 보이는 파일·모듈(있으면).

## 절차
1. **리서치** — 관련 코드·데이터 흐름·기존 패턴·의존성을 **상세히·빠짐없이** 조사. 추측 금지, 근거를 코드에서.
2. 유사 구현(참조)이 있으면 찾아 명시.
3. **계획서 작성** → `docs/plans/<YYYY-MM-DD>-<기능>.md`:
   - 리서치 요약(핵심 파일·흐름·제약)
   - 변경 계획(단계별 · 파일별)
   - 리스크·엣지케이스
   - 검증 방법(어떤 테스트/명령으로 확인)
4. **멈추고 승인 요청.** "계획서를 검토·수정(인라인 노트)하고 승인해 주세요."

## 출력
- `docs/plans/<날짜>-<기능>.md` + 승인 요청 메시지. **코드 변경 없음.**
