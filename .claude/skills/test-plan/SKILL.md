# 테스트 (/test-plan)

## 입력
테스트할 파일/기능, 기존 테스트 프레임워크·스타일.

## 절차
1. **테스트 전략** — 커버할 것: 정상 경로 · 엣지케이스(빈값·경계·예외) · 실패 조건.
2. 기존 테스트 스타일·프레임워크를 따라 작성. (TDD면 실패 테스트를 먼저 작성·커밋 후 구현)
3. **실행**해서 통과 확인. 실패면 원인 분석 → 수정 → 재실행(오류 0까지).
4. **테스트 자체를 리뷰** — `assert true` 같은 무의미한 통과가 아닌지, 실제 동작을 검증하는지.

## 출력
- 테스트 코드 + 실행 결과 + 커버된 케이스 목록. 미검증 영역이 있으면 명시.
