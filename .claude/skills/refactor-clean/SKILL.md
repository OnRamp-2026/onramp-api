# 리팩터·정리 (/refactor-clean)

> **동작을 바꾸지 않는다.** 품질만 개선. 기능 변경은 별도 계획으로.

## 절차
1. 대상 파악(최근 변경 또는 지정 파일).
2. 정리 후보 식별: 데드 코드 · 중복 · 과한 추상화/복잡도 · 안 쓰는 import·파일 · 불필요한 주석.
3. 정리 적용. **각 정리 후 테스트 실행**해 동작 불변 확인(→ `docs/dev-workflow/verification-loop.md`).
4. 위험하거나 판단 필요한 건 자동 삭제하지 말고 **제안**.

## 출력
- 변경 요약(무엇을 왜 정리) + 테스트 통과 확인. 동작 변화 없음 명시.
